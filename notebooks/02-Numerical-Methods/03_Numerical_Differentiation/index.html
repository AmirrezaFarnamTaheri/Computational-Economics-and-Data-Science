    03 Numerical Differentiation¶

    The Lens: The Calculus of the Discrete¶

    What problem are we solving?
    In economics, we constantly need derivatives. Marginal utility is a derivative (\(u'(c)\)). Marginal cost is a derivative (\(C'(q)\)). The first-order condition for optimality sets a derivative to zero. But computers don't know calculus rules; they only know arithmetic. How do we compute a derivative without an analytical formula?

    Why this method?
    We have two main approaches: 1. Finite Differences: Approximate the derivative using the slope between two nearby points. Simple, but prone to errors. 2. Automatic Differentiation (AD): The modern "magic" behind deep learning (JAX, PyTorch). It computes exact derivatives by decomposing code into a graph of elementary operations.

    This notebook moves from the classical approximations to the modern powerhouse of AD.

    Economic question. In 03 Numerical Differentiation, what must remain economically invariant when the computational representation changes? In economic computation, an algorithm is part of the model: convergence tolerances, conditioning, discretization, and stopping rules can alter the apparent equilibrium. The central question is therefore not merely whether a routine returns a number, but whether that number is stable under tighter tolerances, alternative initial conditions, and an independent method. Treat every numerical result as an approximation with a measurable error budget.

    Learning Objectives¶

    By the end of this notebook, you will be able to: 1. Implement Forward, Backward, and Central difference methods. 2. Analyze the trade-off between truncation error and round-off error (the step-size dilemma). 3. Use JAX to compute exact gradients and Hessians automatically. 4. Solve a utility maximization problem using Newton's method with JAX derivatives.

    1. Numerical Differentiation via Finite Differences¶

    The derivative is defined as \(f'(x) = \lim_{h \to 0} \frac{f(x+h) - f(x)}{h}\). Numerically, we just pick a small \(h\). Throughout, \(f: \mathbb{R} \to \mathbb{R}\) is smooth and the step \(h \in \mathbb{R} \setminus \{0\}\); every estimate below approximates the scalar \(f'(x) \in \mathbb{R}\).

    1.1 The Formulas¶

    1. Forward Difference: \(D_+ f(x) = \frac{f(x+h) - f(x)}{h}\). Error: \(O(h)\).
    2. Backward Difference: \(D_- f(x) = \frac{f(x) - f(x-h)}{h}\). Error: \(O(h)\).
    3. Central Difference: \(D_c f(x) = \frac{f(x+h) - f(x-h)}{2h}\). Error: \(O(h^2)\).

    Why Central is Better: By looking both ways, the first-order error terms cancel out, giving significantly higher accuracy for the same step size.

    Derivation via Taylor Series¶

    Figure: Finite-difference error as the step size shrinks.. Expand \(f(x+h)\) and \(f(x-h)\): 1. \(f(x+h) = f(x) + hf'(x) + \frac{h^2}{2}f''(x) + \frac{h^3}{6}f'''(x) + \dots\) 2. \(f(x-h) = f(x) - hf'(x) + \frac{h^2}{2}f''(x) - \frac{h^3}{6}f'''(x) + \dots\)

    Subtracting (2) from (1): $$ f(x+h) - f(x-h) = 2hf'(x) + \frac{h^3}{3}f'''(x) + \dots $$ Dividing by \(2h\) gives: $$ \frac{f(x+h) - f(x-h)}{2h} = f'(x) + \frac{h^2}{6}f'''(x) + \dots $$ The error term starts with \(h^2\), hence it is \(O(h^2)\).

    Richardson Extrapolation¶

    We can eliminate the \(O(h^2)\) error term to get an \(O(h^4)\) approximation. Let \(D(h)\) be the central difference estimate with step \(h\). The error is approximately \(C h^2\). 1. \(D(h) \approx f'(x) + C h^2\) 2. \(D(h/2) \approx f'(x) + C (h/2)^2 = f'(x) + \frac{1}{4} C h^2\)

    Multiply (2) by 4 and subtract (1): $$ 4D(h/2) - D(h) \approx 3f'(x) $$ $$ D_{richardson} = \frac{4D(h/2) - D(h)}{3} = f'(x) + O(h^4) $$

    def forward_diff(f, x, h=1e-5):
    return (f(x + h) - f(x)) / h

def backward_diff(f, x, h=1e-5):
    return (f(x) - f(x - h)) / h

def central_diff(f, x, h=1e-5):
    return (f(x + h) - f(x - h)) / (2 * h)

# Test on f(x) = e^x at x=1 (True derivative is e^1)
f = np.exp
x0 = 1.0
true_val = np.exp(1.0)

print(f"True Value:     {true_val:.8f}")
print(f"Forward (h=1e-4): {forward_diff(f, x0, h=1e-4):.8f}")
print(f"Backward (h=1e-4): {backward_diff(f, x0, h=1e-4):.8f}")
print(f"Central (h=1e-4): {central_diff(f, x0, h=1e-4):.8f} (Much Closer!)")

    1.2 The Step Size Dilemma¶

    Choosing h involves a painful trade-off: * Truncation Error: Increases as h gets larger (math approximation error). * Round-off Error: Increases as h gets smaller (floating-point cancellation error).

    There is a "Goldilocks" zone, typically around \(h \approx \sqrt{\epsilon_{mach}}\) for forward difference and \(h \approx \epsilon_{mach}^{1/3}\) for central difference.

    Why these scales? Rounding noise in a difference quotient behaves like \(\epsilon_{mach}/h\): subtracting nearby values leaves only a few machine-accurate bits in the numerator, which dividing by a tiny \(h\) amplifies. Balancing that against truncation gives the optimum: \(O(h)\) truncation yields \(h \sim \sqrt{\epsilon_{mach}}\), while the central difference's \(O(h^2)\) truncation yields \(h \sim \epsilon_{mach}^{1/3}\).

    2. Automatic Differentiation (AD)¶

    AD is not numerical differentiation (finite differences) and it is not symbolic differentiation (Mathematica).

    AD computes the exact derivative (up to machine precision) by applying the Chain Rule to every elementary operation in your code. It builds a computational graph and passes derivatives through it.

    Forward vs. Reverse Mode¶

    • Forward Mode: Good for functions \(f: \mathbb{R}^m \to \mathbb{R}^n\) with few inputs relative to outputs (\(m \ll n\)).
    • Reverse Mode (Backprop): Good for functions \(f: \mathbb{R}^n \to \mathbb{R}\) (many inputs, one output).

    Economic Context: Most economic problems (Optimization, Maximum Likelihood) involve a scalar objective function with many parameters (\(n \gg 1\)). Thus, Reverse Mode (Backprop) is the standard.

    JVP vs VJP (The Heart of AD)¶

    This distinction explains the efficiency: * JVP (Jacobian-Vector Product): Computes \(Jv\) (directional derivative). This is Forward Mode. One pass gives one column of the Jacobian. Cost scales with inputs \(N\). * VJP (Vector-Jacobian Product): Computes \(v^TJ\) (gradient of linear combination). This is Reverse Mode. One pass gives one row of the Jacobian (the full gradient for scalar output). Cost scales with outputs \(M\).

    Complex Step Differentiation¶

    There is a "magic" trick for functions that can handle complex numbers (like NumPy's exp, sin). Consider the Taylor expansion of \(f(x+ih)\): $$ f(x+ih) = f(x) + ih f'(x) - \frac{h^2}{2} f''(x) - i\frac{h^3}{6} f'''(x) + \dots $$ Taking the imaginary part: $$ \text{Im}(f(x+ih)) = h f'(x) - \frac{h^3}{6} f'''(x) + \dots $$ $$ f'(x) \approx \frac{\text{Im}(f(x+ih))}{h} $$ This has no subtraction! We can make \(h\) extremely small (e.g., \(10^{-100}\)) without any cancellation error, achieving near-exact derivatives.

    Computational Graph¶

    Consider \(y = \ln(x_1) + x_1 x_2\). 1. \(v_1 = \ln(x_1)\) 2. \(v_2 = x_1 x_2\) 3. \(y = v_1 + v_2\)

    AD propagates derivatives through this graph via the Chain Rule.

    Code: Manual Backpropagation¶

    To demystify AD, let's implement a tiny "autograd" engine. We define a Node class that knows its value and how to compute the derivative of its parents.

    class Node:
    def __init__(self, value, parents=None, grad_fn=None):
        self.value = value
        self.parents = parents or []
        self.grad_fn = grad_fn # How to propagate gradient to parents
        self.grad = 0.0

    def backward(self, grad=1.0):
        self.grad += grad
        if self.grad_fn:
            self.grad_fn(grad)  # propagate only this contribution, not the accumulated total

    def __add__(self, other):
        # y = a + b => dy/da = 1, dy/db = 1
        def grad_fn(g):
            self.backward(g)
            other.backward(g)
        return Node(self.value + other.value, [self, other], grad_fn)

    def __mul__(self, other):
        # y = a * b => dy/da = b, dy/db = a
        def grad_fn(g):
            self.backward(g * other.value)
            other.backward(g * self.value)
        return Node(self.value * other.value, [self, other], grad_fn)

# Usage:
# x = Node(2.0); y = Node(3.0); z = x * y + x
# z.backward() 
# print(x.grad) # Should be y + 1 = 4
# Shared intermediate: x = Node(2.0); u = x * x; z = u + u
# z.backward(); print(x.grad) # 8, since z = 2*x**2

    Verbatim Walkthrough: Building AutoDiff from Scratch¶

    Let's build the Forward Mode ourselves using Dual Numbers — the clearest way to see what JAX does under the hood.

    Intuition: Dual Numbers (Forward Mode)¶

    Forward mode can be understood using Dual Numbers of the form \(v + \dot{v}\epsilon\), where \(\epsilon^2 = 0\). This is similar to complex numbers (\(i^2 = -1\)). We define elementary arithmetic: \((a + \dot{a}\epsilon) + (b + \dot{b}\epsilon) = (a+b) + (\dot{a}+\dot{b})\epsilon\) and \((a + \dot{a}\epsilon)(b + \dot{b}\epsilon) = ab + (a\dot{b} + b\dot{a})\epsilon\). Notice that the \(\epsilon\) term automatically carries the derivative rule (product rule in the second case). If we evaluate \(f(x + 1\epsilon)\), the result is \(f(x) + f'(x)\epsilon\). The coefficient of \(\epsilon\) is the exact derivative!

    class Dual:
    def __init__(self, value, grad=0.0):
        self.val = value
        self.grad = grad

    def __repr__(self):
        return f"Dual(val={self.val}, grad={self.grad})"

    def __add__(self, other):
        # (a + be) + (c + de) = (a+c) + (b+d)e
        # Derivative of sum is sum of derivatives
        if isinstance(other, Dual):
            return Dual(self.val + other.val, self.grad + other.grad)
        return Dual(self.val + other, self.grad) # Constant

    def __mul__(self, other):
        # (a + be) * (c + de) = ac + (ad + bc)e + bd(e^2=0)
        # This is exactly the Product Rule: (uv)' = uv' + vu'
        if isinstance(other, Dual):
            new_val = self.val * other.val
            new_grad = self.val * other.grad + self.grad * other.val
            return Dual(new_val, new_grad)
        return Dual(self.val * other, self.grad * other)

    def sin(self):
        # Chain rule: sin(a + be) = sin(a) + cos(a)*b*e
        return Dual(np.sin(self.val), np.cos(self.val) * self.grad)

# Let's differentiate f(x) = x * sin(x) at x=2
x = Dual(2.0, 1.0) # 1.0 seeds the derivative (dx/dx = 1)
y = x * x.sin()

print(f"Function Value: {y.val:.4f}")
print(f"Derivative:     {y.grad:.4f}")

# Verify with analytical rule: sin(x) + x*cos(x)
true_grad = np.sin(2.0) + 2.0 * np.cos(2.0)
print(f"True Deriv:     {true_grad:.4f}")

x0 = 1.5
h_vals = [1e-5, 1e-10, 1e-15, 1e-20]

for h in h_vals:

    3. The JAX Framework¶

    JAX is a Google library that combines NumPy, Automatic Differentiation, and GPU/TPU acceleration. It is becoming the standard for high-performance computational economics.

    Key transformations: * grad(f): Computes the gradient. * jit(f): Just-In-Time compiles the function for speed. * vmap(f): Automatically vectorizes a function.

    The Constraint of Pure Functions¶

    JAX transforms require pure functions: 1. Deterministic: Same input \(\to\) Same output. (No global random state). 2. No Side Effects: No printing, no writing to files, no modifying global variables.

    If you violate this, the JIT compiler will optimize away your side effects or produce unpredictable results.

    if JAX_AVAILABLE:
    # 1. Define a function using JAX numpy
    def f(x):
        return jnp.sin(x) * jnp.exp(-x)

    # 2. Transform it to get gradient and hessian functions
    df = grad(f)
    d2f = hessian(f)

    # 3. Evaluate
    x_val = 1.0
    print(f"f(1.0):    {f(x_val):.6f}")
    print(f"f'(1.0):   {df(x_val):.6f} (Exact)")
    print(f"f''(1.0):  {d2f(x_val):.6f} (Exact)")

    # 4. JIT Compile for speed
    df_fast = jit(df)
    _ = df_fast(x_val) # Trigger compilation
    print("JIT-compiled gradient is ready.")

    4. Application: Utility Maximization¶

    Let's solve a consumer problem: Maximize CES utility subject to a budget constraint. $$ \max_{c_1, c_2} (c_1^\rho + c_2^\rho)^{1/\rho} \quad \text{s.t.} \quad p_1 c_1 + p_2 c_2 = M $$

    We will solve the First-Order Conditions (FOCs) using Newton's Method, where the Jacobian is computed via JAX.

    if JAX_AVAILABLE:
    # Parameters
    p1, p2, M = 2.0, 3.0, 100.0
    rho = 0.5

    # The Lagrangian: L(c1, c2, lam)
    def lagrangian(x):
        c1, c2, lam = x[0], x[1], x[2]
        utility = (c1**rho + c2**rho)**(1/rho)
        constraint = p1*c1 + p2*c2 - M
        return utility - lam * constraint

    # We want to find x such that gradient of Lagrangian is zero
    # FOC function returns the gradient vector
    foc_func = jit(grad(lagrangian))
    # Jacobian of FOCs is the Hessian of the Lagrangian
    jacobian_foc = jit(hessian(lagrangian))

    # Newton's Method
    x = jnp.array([10.0, 10.0, 0.5]) # Initial guess [c1, c2, lambda]

    print("Starting Newton's Method...")
    for i in range(10):
        F = foc_func(x)
        J = jacobian_foc(x)

        # Update: x_new = x_old - J^-1 * F
        step = jnp.linalg.solve(J, -F)
        x = x + step

        error = jnp.linalg.norm(step)
        if error < 1e-8:
            print(f"Converged in {i+1} iterations.")
            break

    print(f"Optimal c1: {x[0]:.4f}")
    print(f"Optimal c2: {x[1]:.4f}")
    print(f"Shadow Price (lambda): {x[2]:.4f}")

    Summary¶

    Key Takeaways: * Finite Differences: Good for quick checks or when you don't have the source code (black box functions). Use Central Difference. * Automatic Differentiation (JAX): The gold standard for modern economic modeling. It gives exact derivatives, is differentiable itself (Hessians!), and runs on GPUs. * Optimization: Combining Newton's Method with AD allows us to solve complex equilibria robustly.
