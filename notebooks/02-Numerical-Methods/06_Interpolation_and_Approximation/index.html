    06 Interpolation and Approximation¶

    The Lens: Connecting the Dots¶

    What problem are we solving?
    In computational economics, we often know the value of a function only at a few specific points (grid points). * We know the Value Function \(V(k)\) at \(k=10, 20, 30\). * But what is \(V(25)\)? What is \(V'(25)\)?

    To evaluate the function between the grid points, we need interpolation.

    Why this method?
    We need to construct a continuous function from discrete data. The choice of method matters: * Linear Interpolation: Safe, preserves monotonicity (good for Value Functions), but not smooth. * Cubic Splines: Smooth (differentiable), but can oscillate. * Chebyshev Polynomials: The "gold standard" for smooth functions in macroeconomics (Spectral convergence).

    The Weierstrass Approximation Theorem¶

    This theorem gives us hope. It states that any continuous function on a closed interval \([a, b]\) can be uniformly approximated as closely as desired by a polynomial function. This justifies our search for the perfect polynomial.

    Basis Functions and Projections¶

    Approximation is often about expressing a complicated function \(f(x)\) as a weighted sum of simpler basis functions \(\phi_i(x)\): $$ f(x) \approx \sum_{i=0}^N c_i \phi_i(x) $$ Finding the weights \(c_i\) is equivalent to projecting the function \(f\) onto the subspace spanned by the basis functions (like regression!). Common bases include monomials (\(x^n\)), Fourier series (\(\{\sin, \cos\}\)), and Chebyshev polynomials.

    Lagrange Basis Polynomials: For interpolation, a convenient basis is the Lagrange basis \(L_i(x)\), defined such that \(L_i(x_j) = 1\) if \(i=j\) and \(0\) if \(i \ne j\). Then the polynomial is simply \(P(x) = \sum y_i L_i(x)\). $$ L_i(x) = \prod_{j \ne i} \frac{x - x_j}{x_i - x_j} $$

    Learning Objectives¶

    By the end of this notebook, you will be able to: 1. Understand the Runge Phenomenon and why equidistant grids are dangerous. 2. Implement Linear and Spline interpolation using scipy. 3. Master Chebyshev interpolation for high-precision approximation. 4. Visualize the "Curse of Dimensionality" and how sparse grids help.

    1. The Runge Phenomenon¶

    Figure: High-degree interpolation oscillating on equispaced nodes..: A Warning

    Intuition suggests that using a higher-degree polynomial to fit more points yields a better approximation. This is wrong.

    For equidistant points, high-degree polynomials oscillate wildly near the boundaries. This is the Runge Phenomenon.

    \[ f(x) = \frac{1}{1 + 25x^2} \]
    def runge(x): return 1 / (1 + 25 * x**2)

x_plot = np.linspace(-1, 1, 500)
n_points = 15

# Equidistant nodes
x_nodes = np.linspace(-1, 1, n_points)
y_nodes = runge(x_nodes)

# High-degree polynomial interpolation
poly = BarycentricInterpolator(x_nodes, y_nodes)
y_poly = poly(x_plot)

plt.figure(figsize=(10, 5))
plt.plot(x_plot, runge(x_plot), 'k-', label='True Function')
plt.plot(x_nodes, y_nodes, 'ko', label='Nodes')
plt.plot(x_plot, y_poly, 'r--', label=f'Poly Order {n_points-1}')
plt.ylim(-0.5, 2)
plt.title("The Runge Phenomenon: High-Degree Polynomials on Equidistant Grids Explode")
plt.legend()
plt.show()

    2. Chebyshev Approximation: The Solution¶

    Figure: Chebyshev nodes tame the oscillation..

    To fix Runge's problem, we cluster the nodes near the endpoints. These are Chebyshev nodes. $$ x_k = \cos\left(\frac{2k-1}{2n}\pi\right) $$

    For a function analytic in a complex neighborhood of the interval, Chebyshev interpolation can achieve geometric (exponential) convergence in \(N\). Infinite smoothness alone does not guarantee an exponential rate; finite differentiability generally gives algebraic convergence.

    The Lebesgue Constant¶

    The maximum error of polynomial interpolation is bounded by \(||f - P_n|| \le (1 + \Lambda_n) ||f - p^*||\), where \(p^*\) is the best possible polynomial approximation. \(\Lambda_n\) is the Lebesgue Constant, which depends only on the node locations. For equidistant nodes, \(\Lambda_n\) grows exponentially with \(n\). For Chebyshev nodes, it grows only on the order of \(\log n\). This explains why Chebyshev is near-optimal.

    Barycentric Interpolation¶

    The standard way to fit a polynomial (solving the Vandermonde system) is numerically unstable for high degrees (\(N > 20\)). The Barycentric Formula is a stable, \(O(N)\) way to evaluate the interpolating polynomial. scipy.interpolate.BarycentricInterpolator uses this method automatically.

    Verbatim Walkthrough: Why Chebyshev Nodes?¶

    Imagine looking at a circle from the side. The points on the rim of the circle are equally spaced in angles (\(0, 2\pi/n, \dots\)). But if you project them down onto the x-axis, they cluster at the ends (-1 and 1) and are sparse in the middle.

    This is exactly what Chebyshev nodes are: the x-coordinates of equidistant points on the upper half of a unit circle. This clustering counteracts the wild oscillations of high-degree polynomials at the boundaries.

    # Chebyshev Nodes
k = np.arange(1, n_points + 1)
x_cheb = np.cos((2*k - 1) / (2*n_points) * np.pi)
y_cheb = runge(x_cheb)

# Interpolation on Chebyshev nodes
poly_cheb = BarycentricInterpolator(x_cheb, y_cheb)
y_poly_cheb = poly_cheb(x_plot)

plt.figure(figsize=(10, 5))
plt.plot(x_plot, runge(x_plot), 'k-', label='True Function')
plt.plot(x_cheb, y_cheb, 'go', label='Chebyshev Nodes')
plt.plot(x_plot, y_poly_cheb, 'g--', label='Chebyshev Interpolation')
plt.title("Chebyshev Nodes Fix the Oscillation")
plt.legend()
plt.show()

    3. Splines and Shape Preservation¶

    Sometimes we don't want a global polynomial. We want to connect the dots piecewise.

    • Linear: Connects dots with lines. Preserves monotonicity but has kinks (discontinuous derivative).
    • Cubic Spline: Connects with cubic polynomials. Smooth derivatives, but can overshoot.
    • PCHIP: Piecewise Cubic Hermite Interpolating Polynomial. Smooth AND preserves monotonicity (note: monotonicity, not concavity - PCHIP cannot create spurious extrema, but it can locally bend the wrong way for concave data). Best for Value Functions.

    Application: Optimal Policy Functions¶

    In Dynamic Programming (Bellman Equations), the Value Function \(V(k)\) is often concave and monotonic. Using a method that violates these properties (like a high-degree polynomial on a coarse grid) can introduce fake local maxima, confusing the optimizer. PCHIP or Linear interpolation is safer.

    # Comparing Interpolation Methods for a Concave Value Function
# True Value Function V(k) = log(k)
k_grid = np.linspace(0.1, 10, 6) # Very coarse grid
v_grid = np.log(k_grid)

k_fine = np.linspace(0.1, 10, 100)
v_true = np.log(k_fine)

# Interpolators
linear_interp = interp1d(k_grid, v_grid, kind='linear')
# CubicSpline defaults to bc_type='not-a-knot' (the third derivative is
# continuous at the two interior-most breaks); pass bc_type='natural' to
# zero the second derivatives at the endpoints instead.
cubic_interp = CubicSpline(k_grid, v_grid)
pchip_interp = PchipInterpolator(k_grid, v_grid)

# Plot
plt.figure(figsize=(10, 6))
plt.plot(k_fine, v_true, 'k-', lw=2, label='True V(k) = log(k)')
plt.plot(k_grid, v_grid, 'ko', label='Grid Points')
plt.plot(k_fine, linear_interp(k_fine), 'b-.', label='Linear (kinks)')
plt.plot(k_fine, cubic_interp(k_fine), 'r--', label='Cubic Spline (Overshoots)')
plt.plot(k_fine, pchip_interp(k_fine), 'g:', lw=3,
         label='PCHIP (Preserves Monotonicity)')
plt.title('Why Shape Preservation Matters in Economics')
plt.legend()
plt.show()

    Multidimensional Splines¶

    Economic models often involve functions of multiple variables, such as a production function \(F(K, L)\) or a utility function \(U(C, L)\). To interpolate these, we use tensor product splines.

    The idea is to construct a grid where every \(x_i\) is paired with every \(y_j\). If the grid is regular (rectangular), scipy.interpolate.RectBivariateSpline is highly efficient. It constructs a 2D surface that passes through the grid points \((x_i, y_j, z_{ij})\).

    from scipy.interpolate import RectBivariateSpline

# Production Function F(K, L) = K^0.3 L^0.7
k_grid = np.linspace(1, 10, 10)
l_grid = np.linspace(1, 10, 10)
K, L = np.meshgrid(k_grid, l_grid)
Y = K**0.3 * L**0.7

# Create Spline
# Note: RectBivariateSpline expects 1D arrays for x and y, and 2D array for z
spline_2d = RectBivariateSpline(l_grid, k_grid, Y)

# Evaluate off-grid at K=5.5, L=5.5
k_eval, l_eval = 5.5, 5.5
y_approx = spline_2d(l_eval, k_eval)[0, 0]
y_true = k_eval**0.3 * l_eval**0.7

print(f"True Output:   {y_true:.4f}")
print(f"Spline Output: {y_approx:.4f}")
print(f"Error:         {abs(y_true - y_approx):.2e}")

    Orthogonal Collocation¶

    In computational economics (especially for solving ODEs or Bellman equations), we often need to find a function \(V(k)\) that satisfies an equation implicitly: $$ R(V(k)) = 0 $$

    Instead of solving for values at grid points (Finite Difference), Collocation methods assume the solution is a weighted sum of basis functions: $$ V(k) \approx \hat{V}(k) = \sum_{i=1}^N c_i \phi_i(k) $$

    We find the coefficients \(c_i\) — equivalently the vector \(c \in \mathbb{R}^N\), one weight per basis function \(\phi_i: \mathbb{R} \to \mathbb{R}\) — by forcing the residual to be zero at \(N\) collocation nodes \(k_1, \dots, k_N \in \mathbb{R}\): $$ R(\hat{V}(k_j)) = 0 \quad \text{for } j=1, \dots, N $$

    If we use Chebyshev polynomials as basis functions and Chebyshev nodes as collocation points, this method is known as Orthogonal Collocation. For analytic solutions and a stable discretization, it can achieve exponential error decay as \(N\) increases; smoothness, boundary conditions, and conditioning determine the rate in a particular problem.

    # Example: Approximating f(x) = exp(x) on [-1, 1] using Chebyshev Collocation
# This is trivial (we know f(x)), but illustrates finding coefficients.

n_nodes = 6
nodes = np.cos((2 * np.arange(1, n_nodes + 1) - 1) / (2 * n_nodes) * np.pi)
y_nodes = np.exp(nodes)

# Vandermonde Matrix for Chebyshev Polynomials
# T_i(x_j)
V = chebyshev.chebvander(nodes, n_nodes - 1)

# Solve for coefficients c: V @ c = y
c = np.linalg.solve(V, y_nodes)

print("Chebyshev Coefficients:")
print(c)

# Reconstruct function at a new point
x_test = 0.5
y_exact = np.exp(x_test)
y_approx = chebyshev.chebval(x_test, c)

print(f"\nVal at x={x_test}: {y_approx:.6f} (Exact: {y_exact:.6f})")
print(f"Error: {abs(y_exact - y_approx):.2e}")

    # Data that is monotonic but has a sharp step (like a CDF or Value Function)
x = np.array([0, 1, 2, 3, 4, 5])
y = np.array([0, 0, 1, 1, 4, 10])

x_fine = np.linspace(0, 5, 100)

cubic = CubicSpline(x, y)(x_fine)
pchip = PchipInterpolator(x, y)(x_fine)

plt.figure(figsize=(10, 5))
plt.plot(x, y, 'ko', label='Data')
plt.plot(x_fine, cubic, 'r--', label='Cubic Spline (Overshoots!)')
plt.plot(x_fine, pchip, 'g-', label='PCHIP (Preserves Shape)')
plt.legend()
plt.title("Shape Preservation: PCHIP vs Cubic Spline")
plt.show()

    4. The Curse of Dimensionality¶

    Interpolating in 1D is easy. In \(D\) dimensions, the number of grid points grows as \(N^D\). * \(N=10, D=1 \implies 10\) points. * \(N=10, D=4 \implies 10,000\) points. * \(N=10, D=10 \implies 10,000,000,000\) points.

    This is why standard grid-based methods become impractical for complex models (e.g., Heterogeneous Agents with many states).

    Solutions: 1. Sparse Grids (Smolyak): Only keep the most "important" cross-terms. If \(f(x, y)\) is smooth, the cross term \(x^N y^N\) has a tiny coefficient. We can drop it without losing much accuracy. Smolyak grids grow as \(N (\log N)^{D-1}\) instead of \(N^D\). 2. Adaptive Grids: Put points only where the function is curved. 3. Neural Networks: Universal function approximators that don't depend on a grid.

    # --- Visualizing Sparse Grids ---
def cheb_nodes_1d(n):
    return np.cos(np.pi * (2*np.arange(1, n+1) - 1) / (2*n))

level = 4
# 1. Full Tensor Grid
nodes_1d = cheb_nodes_1d(2**level + 1)
tensor_x, tensor_y = np.meshgrid(nodes_1d, nodes_1d)

# 2. Simple Smolyak Construction (Visualization Only)
# We combine grids of different resolutions (i, j) such that i + j <= level + 1
smolyak_pts = []
for i in range(1, level + 2):
    for j in range(1, level + 2):
        if i + j <= level + 2: # The sparsity condition
            ni = 2**(i-1) + 1 if i > 1 else 1
            nj = 2**(j-1) + 1 if j > 1 else 1
            pts_i = cheb_nodes_1d(ni)
            pts_j = cheb_nodes_1d(nj)
            for pi in pts_i:
                for pj in pts_j:
                    smolyak_pts.append((pi, pj))

smolyak_pts = np.array(list(set(smolyak_pts))) # Unique points

fig, axes = plt.subplots(1, 2, figsize=(12, 6))
axes[0].scatter(tensor_x, tensor_y, s=10, alpha=0.6)
axes[0].set_title(f"Tensor Grid ({(2**level+1)**2} points)")
axes[0].set_aspect('equal')

axes[1].scatter(smolyak_pts[:,0], smolyak_pts[:,1], s=10, c='red', alpha=0.6)
axes[1].set_title(f"Sparse Grid (~{len(smolyak_pts)} points)")
axes[1].set_aspect('equal')
plt.show()
print("Observation: The sparse grid covers the space efficiently with far fewer points.")

    Dimension notes: approximant \(\hat{f}: \mathbb{R} \to \mathbb{R}\) with coefficients \(c_i \in \mathbb{R}\); Lagrange basis built from distinct nodes \(x_j \in \mathbb{R}\); Runge example lives on \([-1, 1]\); Chebyshev nodes \(x_k \in [-1, 1]\).

    Economic Interpretation: Approximation error becomes policy error¶

    Approximation quality matters because value functions, policy rules, and equilibrium maps are repeatedly evaluated inside solvers. A small local interpolation error can alter an argmax, shift a simulated distribution, and then feed back into market clearing. Chebyshev nodes and sparse grids are useful precisely because they allocate approximation capacity where global polynomial error would otherwise become economically consequential.

    Summary¶

    Key Takeaways: * Avoid Equidistant Polynomials: They oscillate. Use Chebyshev nodes if you can choose your grid. * Value Functions need Shape: Use PchipInterpolator or Linear interpolation for VFI to avoid creating fake local optima. * Smooth Functions need Chebyshev: For Euler equation methods, Chebyshev polynomials are incredibly efficient. * High Dimensions: Tensor-grid sizes grow as \(N^D\), so they become impractical after a few dimensions. You need smarter methods.
