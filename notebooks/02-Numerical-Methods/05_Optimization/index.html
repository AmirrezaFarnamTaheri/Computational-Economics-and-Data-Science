    05 Optimization¶

    The Lens: The Rational Agent's Toolkit¶

    What problem are we solving?
    The central behavioral assumption in economics is optimization. * Households maximize utility. * Firms maximize profit. * Governments maximize social welfare. * Econometricians minimize error (Maximum Likelihood is just minimization of negative log-likelihood).

    Mathematically, this means finding the vector \(x\) that minimizes an objective function \(f(x)\) subject to constraints \(g(x) \le 0\).

    Why this method?
    We need algorithms to find the peak of the mountain. * Local Search (BFGS): Like climbing a hill in the fog. Fast, but can get stuck in local optima. * Global Search (Differential Evolution): Like parachuting into a mountain range. Good for rugged landscapes. * Convex Optimization (CVXPY): If the hill is shaped like a bowl, we can find the absolute bottom instantly.

    Economic question. In 05 Optimization, what must remain economically invariant when the computational representation changes? In economic computation, an algorithm is part of the model: convergence tolerances, conditioning, discretization, and stopping rules can alter the apparent equilibrium. The central question is therefore not merely whether a routine returns a number, but whether that number is stable under tighter tolerances, alternative initial conditions, and an independent method. Treat every numerical result as an approximation with a measurable error budget.

    Learning Objectives¶

    By the end of this notebook, you will be able to: 1. Distinguish between convex and non-convex problems. 2. Apply BFGS and Nelder-Mead for unconstrained optimization. 3. Solve constrained consumer problems using SLSQP. 4. Use CVXPY for disciplined convex programming. 5. Visualize optimization landscapes in 3D.

    1. Unconstrained Optimization¶

    We seek \(\min_x f(x)\).

    1.1 The Intuition: Climbing a Hill Blindfolded¶

    Imagine you are on a mountain range in thick fog. You want to find the lowest valley. How do you move?

    • Gradient Descent: You feel the slope under your feet. If it slopes down to the right, you step right. You take a step proportional to the steepness. This is slow because you zigzag.
    • Newton's Method: You not only feel the slope (Gradient) but also how the slope is changing (Curvature/Hessian). If the slope is getting shallower, you know the bottom is near, so you jump straight there. This is fast (Quadratic convergence) but requires knowing the curvature.

    BFGS is a "Quasi-Newton" method. It doesn't calculate the curvature exactly (which is expensive) but builds up an approximation of it as it walks. It is the gold standard for general optimization.

    Intuition: Imagine trying to map the curvature of the hill. After each step, you see how much the gradient changed. A large change in gradient for a small step means high curvature (steep walls). BFGS uses this "secant condition" to update its internal map (Inverse Hessian approximation) at every step.

    Line Search & Wolfe Conditions: Finding the search direction \(p_k\) is only half the battle. We also need the step size \(\alpha_k\). We don't just minimize along the line (exact search is expensive). We look for an \(\alpha_k\) that satisfies the Wolfe Conditions: 1. Armijo Rule (Sufficient Decrease): The objective must decrease enough relative to the slope. 2. Curvature Condition: The slope at the new point must be less steep than at the start (ensuring we didn't stop too early on a steep slope).

    Trust Region Methods: Instead of choosing a direction and then a step size (Line Search), Trust Region methods choose a maximum step size \(\Delta\) (the region where we trust our quadratic approximation) and then find the best point within that radius. * If the approximation is good, we expand \(\Delta\). * If bad, we shrink \(\Delta\). This is more robust for non-convex problems than line search. scipy.optimize uses this in method='trust-constr'.

    Visualizing the Path¶

    Let's minimize the Rosenbrock function (the "banana valley"), a classic test case for optimizers. It has a global minimum at \((1, 1)\) inside a long, narrow, curved valley. We race Nelder-Mead (derivative-free) against BFGS supplied with the analytic gradient via jac=rosen_2d_grad; the step counts in the legend show why handing the optimizer exact derivatives is almost always worth the calculus.

    def rosen_2d(x):
    return (1 - x[0])**2 + 100 * (x[1] - x[0]**2)**2

def rosen_2d_grad(x):
    # Analytic gradient; exact derivatives beat finite differences
    # inside Rosenbrock's narrow curved valley.
    return np.array([
        -2 * (1 - x[0]) - 400 * x[0] * (x[1] - x[0]**2),
        200 * (x[1] - x[0]**2),
    ])

# Track the path
path_nm = []
path_bfgs = []

x0 = np.array([-1.5, 1.5])

# 1. Nelder-Mead (Gradient-Free Simplex)
res_nm = minimize(rosen_2d, x0, method='Nelder-Mead', callback=lambda x: path_nm.append(x))

# 2. BFGS (Quasi-Newton)
res_bfgs = minimize(rosen_2d, x0, method='BFGS', jac=rosen_2d_grad,
                    callback=lambda x: path_bfgs.append(x))

# Plotting
x = np.linspace(-2, 2, 100)
y = np.linspace(-1, 3, 100)
X, Y = np.meshgrid(x, y)
Z = (1 - X)**2 + 100 * (Y - X**2)**2

fig, ax = plt.subplots(figsize=(10, 7))
ax.contour(X, Y, np.log(Z), levels=30, cmap='gray_r')

path_nm = np.array(path_nm)
path_bfgs = np.array(path_bfgs)

ax.plot(path_nm[:,0], path_nm[:,1], 'b.-', label=f'Nelder-Mead ({len(path_nm)} steps)')
ax.plot(path_bfgs[:,0], path_bfgs[:,1], 'r.-', label=f'BFGS ({len(path_bfgs)} steps)')
ax.plot(1, 1, 'k*', markersize=15, label='Global Min (1,1)')

    2. Convex Optimization (CVXPY)¶

    A function is convex if the line between any two points lies above the graph. The Superpower: Any local minimum of a convex function is the global minimum.

    CVXPY is a library for "Disciplined Convex Programming". It checks if your problem is convex before solving it.

    Why is Convexity a Superpower?¶

    In a convex problem, the Hessian is positive semi-definite everywhere. This means the function curves upward in all directions. If you find a point where the gradient is zero (flat), you are guaranteed to be at the absolute bottom of the bowl. There are no hidden valleys or traps. This allows solvers to be incredibly efficient and reliable.

    if CVXPY_AVAILABLE:
    # Problem: Maximize Log Utility subject to Budget
    # max 0.5*log(x) + 0.5*log(y) s.t. 2x + 4y <= 100

    # Variables
    x = cp.Variable(pos=True)
    y = cp.Variable(pos=True)

    # Parameters
    alpha = 0.5
    px, py, I = 2, 4, 100

    # Objective (Note: CVXPY maximizes concave functions)
    # log is concave, sum of concave is concave.
    utility = alpha * cp.log(x) + (1 - alpha) * cp.log(y)
    objective = cp.Maximize(utility)

    # Constraints
    constraints = [px * x + py * y <= I]

    # Solve
    prob = cp.Problem(objective, constraints)
    prob.solve()

    print(f"Status: {prob.status}")
    print(f"Optimal Bundle: x={x.value:.2f}, y={y.value:.2f}")
    print(f"Max Utility: {prob.value:.4f}")

    3. Constrained Optimization (SLSQP)¶

    When problems are non-convex or too complex for CVXPY, we use Sequential Least Squares Programming (SLSQP). It handles equality and inequality constraints.

    Application: The Consumer's Problem¶

    \[ \max_{x,y} x^\alpha y^{1-\alpha} \quad \text{s.t.} \quad p_x x + p_y y = I \]

    All quantities are scalars: quantities \(x, y \in \mathbb{R}_{++}\), prices \(p_x, p_y > 0\), income \(I > 0\), preference share \(\alpha \in (0, 1)\).

    Karush-Kuhn-Tucker (KKT) Conditions¶

    Under a constraint qualification (for example, linearly independent active constraint gradients), the KKT conditions are necessary for a local optimum of a differentiable constrained problem. They generalize Lagrange multipliers. Here we use minimization with \(h(x)=0\) and \(g(x)\le0\). For a solution \(x^* \in \mathbb{R}^n\) to be optimal — with objective \(f: \mathbb{R}^n \to \mathbb{R}\), equality constraint \(h: \mathbb{R}^n \to \mathbb{R}\), and inequality constraint \(g: \mathbb{R}^n \to \mathbb{R}\) — there must exist multipliers \(\lambda \in \mathbb{R}\) (for equality) and \(\mu \ge 0\) (for inequality) such that: 1. Stationarity: \(\nabla f(x^*) + \lambda \nabla h(x^*) + \mu \nabla g(x^*) = 0\) 2. Primal Feasibility: Constraints are satisfied. 3. Dual Feasibility: \(\mu \ge 0\). 4. Complementary Slackness: \(\mu g(x^*) = 0\). (Either the constraint binds, or the multiplier is zero).

    The Economics of Duality: The multipliers \(\lambda\) and \(\mu\) are Shadow Prices. They tell us how much the objective function (utility/profit) would improve if we relaxed the constraint by one unit. In the consumer problem, \(\mu\) is the marginal utility of income.

    The Envelope Theorem: A Zero-to-Hero Explanation¶

    The Envelope Theorem is one of the most powerful tools in economics. It tells us how the optimized value of a function changes when a parameter changes.

    The Setup: Let \(V(\theta) = \max_x f(x, \theta)\) be the value function, where \(x\) is the choice variable and \(\theta\) is a parameter (like income \(I\) or price \(p\)). Let \(x^*(\theta)\) be the optimal choice for a given \(\theta\). So \(V(\theta) = f(x^*(\theta), \theta)\).

    The Question: How does \(V\) change when \(\theta\) changes? $$ \frac{dV}{d\theta} = \frac{\partial f}{\partial x} \frac{dx^*}{d\theta} + \frac{\partial f}{\partial \theta} $$

    The Insight: For a differentiable interior unconstrained optimum, the First Order Condition (FOC) holds: \(\frac{\partial f}{\partial x} = 0\). Therefore, the first term vanishes! $$ \frac{dV}{d\theta} = \frac{\partial f(x^*, \theta)}{\partial \theta} = \frac{\partial \mathcal{L}}{\partial \theta} $$

    Constrained case: With parameter-dependent constraints, use the partial derivative of the Lagrangian, including constraint terms, under the relevant regularity conditions. The objective gradient alone need not vanish; for example, a consumer budget binds.

    Meaning: We can ignore the fact that the agent re-optimizes (\(dx^*/d\theta\)) when calculating the first-order effect on the value function. We only need to look at the direct effect of the parameter change.

    Verbatim Walkthrough: Geometric Derivation of KKT¶

    Let's visualize exactly why the gradients must align. Consider maximizing \(f(x, y)\) subject to \(g(x, y) = c\).

    1. Level Sets: Think of \(f(x, y)\) as a mountain. The level sets (contour lines) are rings around the peak.
    2. Constraint: The constraint \(g(x, y) = c\) is a path you must walk on.
    3. Crossing Contours: If the path crosses a contour line of \(f\), you can still move along the path to reach a higher contour. This means you are not at the optimum.
    4. Tangency: You stop improving only when your path is tangent to a contour line. At this point, you cannot move up without leaving the path.
    5. Normal Vectors: If two curves are tangent, their normal vectors (gradients) are parallel. The gradient of the objective \(\nabla f\) points uphill. The gradient of the constraint \(\nabla g\) points perpendicular to the path.

    Therefore, \(\nabla f\) must be a multiple of \(\nabla g\): $$ \nabla f(x^) = \lambda \nabla g(x^) $$ or \(\nabla f - \lambda \nabla g = 0\). This is the stationarity condition!

    Optimality: No Feasible Descent Direction¶

    1. Feasible Direction: Imagine you are at a point on the boundary \(g(x)=0\). Any movement inside the feasible set must make an angle of \(\ge 90^\circ\) with the constraint gradient \(\nabla g\). (Otherwise you'd walk out of the set).
    2. Descent Direction: To improve the objective (minimize \(f\)), you want to move opposite to \(\nabla f\).
    3. Optimality: If you are at the optimum, there is no direction that is both feasible and a descent direction.
    4. Conclusion: The direction of steepest descent (\(-\nabla f\)) must point exactly perpendicular to the constraint boundary surface, pointing in the same direction as the outward constraint gradient (\(\nabla g\)) when the single active inequality has a positive multiplier. Thus, \(\nabla f = -\lambda \nabla g\).

    Application: Mean-Variance Portfolio Optimization¶

    A cornerstone of modern finance is Markowitz Portfolio Theory. We want to minimize risk (variance) for a given level of return.

    Problem: \(\min_w \frac{1}{2} w^T \Sigma w \quad \text{s.t.} \quad \mu^T w \ge R, \quad \mathbf{1}^T w = 1\)

    Dimensions: weights \(w \in \mathbb{R}^N\), expected returns \(\mu \in \mathbb{R}^N\), covariance \(\Sigma \in \mathbb{R}^{N \times N}\) symmetric positive semi-definite, \(\mathbf{1} \in \mathbb{R}^N\) the ones vector; the objective maps \(\mathbb{R}^N \to \mathbb{R}\).

    Derivation: The Lagrangian is \(\mathcal{L} = \frac{1}{2} w^T \Sigma w - \lambda (w^T \mu - R) - \gamma (w^T \mathbf{1} - 1)\). FOC w.r.t \(w\): \(\Sigma w - \lambda \mu - \gamma \mathbf{1} = 0 \implies w^* = \Sigma^{-1} (\lambda \mu + \gamma \mathbf{1})\). The weights are a linear combination of the "tangency portfolio" (driven by \(\mu\)) and the "minimum variance portfolio" (driven by \(\mathbf{1}\)). As we vary \(R\) (and thus \(\lambda\)), we trace out the Efficient Frontier.

    SQP vs. Interior Point Methods¶

    • SQP (Sequential Quadratic Programming): Solves a sequence of quadratic approximations. Generally faster for small-to-medium problems with smooth constraints (like our consumer problem). method='SLSQP'.
    • Interior Point: Follows a path through the interior of the feasible region. Better for large-scale problems or when the solution must be strictly feasible at all times. method='trust-constr'.
    # Objective: Minimize NEGATIVE utility
def neg_utility(z, alpha):
    x, y = z
    return -(x**alpha * y**(1-alpha))

def neg_utility_grad(z, alpha):
    # jac must be the gradient OF THE MINIMIZED objective, i.e. of the
    # negative utility - not of the utility itself.
    x, y = (max(v, 1e-12) for v in z)  # guard the x=0 or y=0 bound
    u = x**alpha * y**(1-alpha)
    return np.array([-alpha * u / x, -(1 - alpha) * u / y])

# Constraint: I - px*x - py*y >= 0 (Inequality form for minimize)
def budget_constraint(z, px, py, I):
    x, y = z
    return I - px*x - py*y

# Parameters
params = (0.5,) # alpha
cons_args = (2, 4, 100) # px, py, I

# Setup
cons = {'type': 'ineq', 'fun': budget_constraint, 'args': cons_args}
bnds = ((0, None), (0, None)) # x, y >= 0
z0 = [10, 10]

# Solve
res = minimize(neg_utility, z0, args=params, method='SLSQP',
               jac=neg_utility_grad, bounds=bnds, constraints=cons)

print(f"Success: {res.success}")
print(f"Optimal x: {res.x[0]:.2f}")
print(f"Optimal y: {res.x[1]:.2f}")

    if CVXPY_AVAILABLE:
    # --- Mean-Variance Portfolio Optimization ---
    rng = np.random.default_rng(42)
    n_assets = 5
    mu = np.abs(rng.standard_normal((n_assets, 1))) # Expected returns
    Sigma = rng.standard_normal((n_assets, n_assets))
    Sigma = Sigma.T @ Sigma # Make positive semi-definite

    w = cp.Variable(n_assets)
    gamma = cp.Parameter(nonneg=True) # Risk aversion parameter

    # Objective: Maximize Return - gamma * Risk
    ret = mu.T @ w
    risk = cp.quad_form(w, Sigma)
    objective = cp.Maximize(ret - gamma * risk)

    # Constraints: Fully invested, Long only
    constraints = [cp.sum(w) == 1, w >= 0]

    prob = cp.Problem(objective, constraints)

    # Compute Efficient Frontier
    gamma_vals = np.logspace(-2, 3, 50)
    risk_data = np.zeros(len(gamma_vals))
    ret_data = np.zeros(len(gamma_vals))

    for i, val in enumerate(gamma_vals):
        gamma.value = val
        prob.solve()
        risk_data[i] = cp.sqrt(risk).value
        ret_data[i] = ret.value

    plt.figure(figsize=(8, 5))
    plt.plot(risk_data, ret_data, 'b-', label='Efficient Frontier')
    plt.xlabel('Risk (Standard Deviation)')
    plt.ylabel('Return')
    plt.title('Markowitz Efficient Frontier (via CVXPY)')
    plt.legend()
    plt.grid(True)
    plt.show()

    4. Global Optimization¶

    If your function has many local minima (like a rugged mountain range), BFGS will get stuck. Use Differential Evolution.

    Example: The Eggholder Function¶

    A notoriously difficult function with many local minima.

    def eggholder(x):
    return (-(x[1] + 47) * np.sin(np.sqrt(abs(x[0]/2 + (x[1]  + 47))))
            -x[0] * np.sin(np.sqrt(abs(x[0] - (x[1]  + 47)))))

bounds = [(-512, 512), (-512, 512)]

# 1. Try local search. With bounds and no method argument, scipy's
#    default pick is L-BFGS-B; we name it explicitly so the label below
#    describes what actually ran.
res_local = minimize(eggholder, [0, 0], bounds=bounds, method='L-BFGS-B')

# 2. Try global search
res_global = differential_evolution(eggholder, bounds)

print(f"Local Min (L-BFGS-B): {res_local.fun:.2f} at {res_local.x}")
print(f"Global Min (DiffEv): {res_global.fun:.2f} at {res_global.x}")
print("Notice the massive difference!")

    Key Equations¶

    These relations are collected from the derivations above as a review map. Their assumptions and derivations remain part of the result; this box is not a substitute for them.

    1. Core relation

    \[\max_{x,y} x^\alpha y^{1-\alpha} \quad \text{s.t.} \quad p_x x + p_y y = I\]

    2. Core relation

    \[\frac{dV}{d\theta} = \frac{\partial f}{\partial x} \frac{dx^*}{d\theta} + \frac{\partial f}{\partial \theta}\]

    3. Envelope relation (differentiable interior unconstrained optimum; constrained problems require the Lagrangian including constraints)

    \[\frac{dV}{d\theta} = \frac{\partial f(x^*, \theta)}{\partial \theta} = \frac{\partial \mathcal{L}}{\partial \theta}\]

    4. Core relation

    \[\nabla f(x^*) = \lambda \nabla g(x^*)\]

    Dimension notes: consumer problem — scalars \(x, y, p_x, p_y, I \in \mathbb{R}_{++}\) with \(\alpha \in (0, 1)\). Envelope theorem — value function \(V: \mathbb{R} \to \mathbb{R}\), policy \(x^*(\theta) \in \mathbb{R}\). Portfolio problem — \(w, \mu \in \mathbb{R}^N\), \(\Sigma \in \mathbb{R}^{N \times N}\).

    Summary¶

    Key Takeaways: * Convex? Use CVXPY. It's robust and mathematically guaranteed. * Smooth & Local? Use minimize(method='BFGS') or SLSQP for constraints. * Rugged & Global? Use differential_evolution. * Visualizing: Always try to visualize the objective function in 2D/3D to understand the difficulty.

    Common Pitfalls in This Lecture

    • Local optima. Gradient-based and simplex methods stop at the first local optimum. For non-convex problems, use multiple starting points, global heuristics, or — best — reformulate the problem as convex so local is global.
    • Ignoring solver status. result.x is returned even when the solver failed. Always inspect result.success, result.message, and gradient norm; and rescale badly conditioned problems (variables differing by orders of magnitude) before blaming the algorithm.
