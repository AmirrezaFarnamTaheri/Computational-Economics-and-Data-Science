    1. Introduction

    The Lens: From Notebooks to Publications¶

    What problem are we solving? Jupyter notebooks are excellent for development, but they are not publication-ready documents. Sharing research requires polished reports, slides, and websites. Quarto bridges this gap by rendering notebooks into professional HTML, PDF, and presentation formats with minimal configuration.

    Why this method? Quarto is the successor to R Markdown, designed for multilingual scientific publishing. It turns your existing notebooks into reproducible, publication-quality outputs without leaving the computational workflow.

    Economic question. In 01 Publishing with Quarto, what must remain economically invariant when the computational representation changes? This mathematical result earns its place in the curriculum because later economic arguments rely on its hypotheses, not only its conclusion. As you read each derivation, track which assumption licenses each step and construct a counterexample when an assumption is removed. The objective is to make the theorem usable as a diagnostic tool in optimization, probability, econometrics, or dynamic models rather than a formula to memorize.

    Learning Objectives¶

    • Configure Quarto projects to render notebooks as HTML reports, PDF articles, and slides.
    • Customize output with YAML front matter, cross-references, and citation management.
    • Publish rendered documents to GitHub Pages or Quarto Pub.

    Prerequisites¶

    • Jupyter Notebooks: Ability to create and run notebooks with code, markdown, and plots.
    • Command Line: Basic terminal usage for running quarto render.
    • Learning-path prerequisite: A4-Linear-Algebra.ipynb

    Learning path: Building on A4-Linear-Algebra.ipynb; next continue with T2_Replication_Exercise_Chetty_2014.ipynb.

    Introduction¶

    A collection of Jupyter notebooks in a GitHub repository is excellent for development but falls short for presenting a polished course or research project. This "last mile" problem includes significant barriers for end-users, such as environment setup, lack of clear navigation, and a poor reading experience on platforms like GitHub.

    Quarto is a modern, open-source scientific publishing system designed to solve this problem. It transforms computational documents (like Jupyter notebooks or its native .qmd format) into beautiful, accessible, and reproducible websites, books, presentations, and articles. This chapter provides a complete guide to turning a collection of notebooks into a professional website.

    Learning Objectives¶

    By the end of this chapter, you will be able to:

    • Understand the Quarto Paradigm: Explain the benefits of a modern scientific publishing system for creating reproducible and professional content.
    • Master the Quarto Workflow: Use the Quarto command-line interface (CLI) to initialize, configure, preview, and render a complete website.
    • Structure a Website: Skillfully edit the _quarto.yml configuration file to control the project's title, navigation, appearance, and content structure.
    • Leverage Advanced Features: Use callouts, cross-references, and interactive plots to create sophisticated, polished documents.
    • Automate Publishing: Implement a GitHub Actions workflow for continuous deployment, automatically publishing your website upon changes.

    1. The Quarto Workflow: A Quick Start¶

    The best way to learn Quarto is by building a small project. The workflow centers on a few key commands and one central configuration file.

    Step 1: Install Quarto¶

    Download and install the Quarto CLI from quarto.org.

    Step 2: Create a Project and Files¶

    In your terminal, create a project directory and the necessary files: 

    mkdir my-quarto-site
cd my-quarto-site
touch _quarto.yml index.qmd analysis.ipynb

    Step 3: Add Content¶

    1. Configure _quarto.yml: This file is the brain of your site. Add the following content to it. This structure defines the project type, website title, and a navigation sidebar.

      # _quarto.yml
project:
  type: website

website:
  title: "My Data Analysis Project"
  sidebar:
    contents:
      - href: index.qmd
        text: Home
      - href: analysis.ipynb
        text: Data Analysis

format:
  html:
    theme: cosmo
    toc: true
    code-fold: true

    2. Create a Homepage (index.qmd): This will be the main landing page. 

      ---
title: "Welcome to My Project"
---

This website presents the data analysis for my project.
Please see the **Data Analysis** page for the results.

    3. Add a Notebook (analysis.ipynb): Copy the JSON content below into your analysis.ipynb file. This is a simple notebook that generates a plot. 

      {
 "cells": [
  {
   "cell_type": "markdown",
   "metadata": {},
   "source": ["# Data Analysis Results"]
  },
  {
   "cell_type": "code",
   "execution_count": null,
   "metadata": {},
   "outputs": [],
   "source": [
    "import matplotlib.pyplot as plt\n",
    "import numpy as np\n",
    "x = np.linspace(0, 10, 100)\n",
    "plt.plot(x, np.sin(x))\n",
    "plt.title('Sine Wave')\n",
    "plt.show()"
   ]
  }
 ],
 "metadata": {},
 "nbformat": 4,
 "nbformat_minor": 4
}

    Step 4: Preview and Render¶

    Now, use the Quarto CLI to build and view your site: - quarto preview: Starts a local web server that automatically rebuilds the site when you save a file. This is for development. - quarto render: Performs a clean, one-time build of the entire website, executing all code. The output is saved to a _site directory.

    Run quarto preview in your terminal. Your browser should open to a fully functional two-page website.

    2. Advanced Configuration and Features¶

    Quarto's power lies in its deep customizability and features designed for scientific content.

    2.1. Callouts for Emphasis¶

    Callouts are an excellent way to highlight information. Quarto provides five types: note, tip, warning, caution, and important.

    ::: {.callout-note}
## This is a Note
The Taylor Principle is a necessary but not sufficient condition for stability.
:::

::: {.callout-warning}
Ensure your data is stationary before running a VAR model.
:::

    ## 3. Automation with GitHub Actions

We can use **GitHub Actions**, a continuous integration and deployment (CI/CD) platform, to automatically render and publish our website. This ensures the live version is always in sync with the repository's `main` branch.

Create a file at `.github/workflows/publish.yml` in your repository with the following content. This workflow checks out your code, installs dependencies, renders the site, and deploys it to GitHub Pages.

```yaml
## .github/workflows/publish.yml
name: Publish Website to GitHub Pages

on:
  push:
    branches: [ main ]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pages: write
      id-token: write

    steps:
      - name: Check out repository
        uses: actions/checkout@v4

      - name: Set up Quarto
        uses: quarto-dev/quarto-actions/setup@v2

      - name: Install Python and Dependencies
        uses: actions/setup-python@v4
        with:
          python-version: '3.11'
      - name: Install project requirements
        run: pip install -r requirements.txt

      - name: Render Quarto Website
        run: quarto render
        env:
          # Ensures matplotlib works in a headless environment
          MPLBACKEND: Agg

      - name: Deploy to GitHub Pages
        uses: actions/deploy-pages@v4

    Three-Tier Practice Ladder¶

    1. Mechanism and assumptions (Conceptual): Restate one theorem used in 01 Publishing with Quarto with every hypothesis explicit. Prove one non-trivial step that is often skipped and explain where that step is used later in the curriculum.

    2. Reproduce and diagnose (Applied): Work a concrete example from 1. The Quarto Workflow: A Quick Start, Step 1: Install Quarto by hand and verify it computationally. Show the intermediate algebra, not only the final result.

    3. Robust extension (Challenge): Remove one hypothesis and construct a counterexample or boundary case. Explain exactly which line of the original proof fails and what weaker conclusion, if any, remains.

    3b. Failure analysis (Challenge): A collaborator's quarto render fails on a missing LaTeX engine, and two figures resolve on your machine only. Diagnose the undeclared engine dependency and absolute paths, repair with a self-contained project (bundled assets, documented engine requirement), and verify on a fresh clone.

    Use the existing exercises above when they target the same skill; this ladder makes the intended progression explicit rather than replacing instructor-authored problems.

    4. Exercises¶

    1. Build the Quick Start Site: Follow the steps in Section 1 to create the simple two-page website. Experiment with changing the theme in _quarto.yml to another Bootswatch theme, such as sandstone or darkly. Run quarto preview to see your changes.

    2. Add an Interactive Plot: Install plotly (pip install plotly). In the analysis.ipynb notebook, add a new code cell and create an interactive scatter plot using plotly.express. Render the site and verify that the plot is interactive.

    3. Create a Presentation: Create a new file named presentation.qmd. Add the YAML header for a revealjs presentation as shown in Section 2.3. Create at least three slides, one of which contains a code chunk that displays a plot. Render it with quarto render presentation.qmd.

    4. Customize Your Site: Add a new page to your Quick Start site called about.qmd. Write a brief bio in it. Add this page to the sidebar in _quarto.yml and add a link to your GitHub profile in the top navbar.
