## 1. The Constitution: Global Standards

These rules are non-negotiable. Every single notebook in the repository must adhere to them to ensure consistency, maintainability, and pedagogical excellence.

### I. Structure & Narrative (Task 1 & 6)
*   **The "Lens" Introduction:** Every notebook must begin with a Markdown cell titled `# Introduction` or `# The Lens`. It must answer: *What economic problem are we solving? Why do we need this method?* No cold starts with code.
*   **The "Summary" Conclusion:** Every notebook must end with a `# Summary` or `# Conclusion` section. It must recap: *What did we learn? What is the key takeaway?*
*   **No "Magic" Helpers:** Custom functions like `sec(title)` or `note(msg)` are strictly forbidden. Use standard Markdown (`## Title`) and blockquotes (`> **Note:**`).
*   **Tone:** Professional, direct, active voice. Avoid marketing fluff ("deep dive", "unleash", "comprehensive").

### II. Visuals & Assets (Task 2 & 3)
*   **Unified Style:** Every notebook must apply the standard style in the setup cell:
    ```python
    import matplotlib.pyplot as plt
    import seaborn as sns
    plt.style.use('seaborn-v0_8-whitegrid')
    plt.rcParams.update({'figure.figsize': (10, 6), 'font.size': 12})
    ```
*   **Static vs. Dynamic:** Complex educational diagrams (e.g., payoff trees, supply/demand shifts) should be generated by scripts in `scripts/`, saved to `images/`, and embedded as static images. Data plots (e.g., time series, regression lines) should be generated inline.
*   **Metadata:** All static images must have an entry in `images/metadata.json` with source, license, and description.

### III. Code & Correctness (Task 4)
*   **No Hardcoding:** Analytical solutions (like `P_sol` in RBC) must be computed, not hardcoded arrays. Use `scipy.linalg` or similar.
*   **Robust Data Loading:** `pandas_datareader` or API calls must be wrapped in `try/except` blocks with a fallback to local CSVs in `data/`.
*   **Dependencies:** No inline `!pip install`. All dependencies must be in `requirements.txt`.

## 3. The "Hit List": Critical Refactors (Task 4 & 5)

These are the complex, non-trivial engineering tasks that require focused attention.

1.  **Macro / RBC Solver (`04-Macro-Models/03_RBC_Models.ipynb`):**
    *   **Issue:** The solution matrices `P_sol`, `Q_sol` are hardcoded.
    *   **Fix:** Implement `scripts/klein_solver.py` (Paul Klein's QZ method) or use `scipy.linalg.ordqz` to solve the linearized system dynamically given parameters $\alpha, \beta, \delta$.

2.  **Micro / Heckscher-Ohlin (`05-Micro-Models/02_General_Equilibrium.ipynb`):**
    *   **Issue:** The "world excess demand" function is a placeholder.
    *   **Fix:** Implement a 2-country, 2-good, 2-factor CGE solver using `scipy.optimize.root` that solves for relative prices $(p, w, r)$.

3.  **Econ / SMM Estimation (`03-Economic-Modeling/04_Estimation_and_Calibration.ipynb`):**
    *   **Issue:** The objective function minimizes a dummy mathematical function, not an economic moment distance.
    *   **Fix:** Create a synthetic dataset (e.g., from a true model parameterization) and implement a real SMM routine that estimates $\beta$ or risk aversion by matching moments (e.g., wealth/income ratio).

4.  **Finance / Black-Litterman (`09-Finance/02_Portfolio_Theory.ipynb`):**
    *   **Issue:** Relies on live `yfinance` data which flakes.
    *   **Fix:** Cache `fama_french_5_factors.csv` and `sp500_returns.csv` in `data/`. Update notebook to try loading from CSV first.

5.  **Time Series / GARCH (`08-Time-Series/05_Volatility_Modeling_ARCH_GARCH.ipynb`):**
    *   **Issue:** Relies on `yfinance` for SP500 data.
    *   **Fix:** Ensure `data/SP500.csv` exists and is used as fallback.
